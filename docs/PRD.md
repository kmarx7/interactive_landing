# ILS v1.1 제품 요구사항

## 목표와 사용자

주제와 무관하게 콘텐츠·디자인·인터랙션을 편집해 코딩 없이 랜딩페이지를 만드는 1인 제작자와 교육·문화·SaaS 운영자. 초기 전달물은 로컬 독립형 Next.js 앱이다.

## 핵심 여정

1. 대시보드 → 템플릿 선택 → 프로젝트 생성과 IndexedDB 저장
2. 섹션 선택 → Inspector 편집 → 실시간 렌더링 → 자동 저장 확인
3. 스타일 / 팔레트 변경 → 콘텐츠와 인터랙션 설정 보존
4. Preview → 실제 탭 / 체크리스트 / 시뮬레이터 조작
5. JSON 다운로드 → 가져오기 → 새 프로젝트로 복원

## 수용 기준

- 저장 성공은 IndexedDB transaction complete 이후에만 표시한다.
- 저장 실패 시 편집본을 유지하고 재시도·백업을 제공한다.
- 스키마 버전, 타입, 수치 범위, 색상, URL을 검증한다.
- JSON을 코드로 실행하지 않고 등록된 타입만 렌더링한다.
- 복원은 기존 ID를 새 UUID로 교체해 다른 프로젝트를 덮어쓰지 않는다.
- 삭제·템플릿 교체는 확인하며 섹션 삭제는 Undo 가능하다.
- 편집에서 입력은 선택에 쓰고, 미리보기에서만 인터랙션을 실행한다.
- 세 가지 주제가 같은 컴포넌트와 저장 모델을 사용한다.
- 준비 중 기능은 사용 가능한 기능처럼 표시하지 않는다.

## 스타일과 블록 범위

30종 카탈로그, 대표 3종 적용. 팔레트 6종은 두 명암 변형을 갖는다. 요청 목록은 실제로 31종 인터랙션이며 공통 Hero를 더해 32종 블록으로 구성한다. 각 블록은 초기 기능 구현이며 모든 고급 변형이 완성된 것은 아니다.

## 비기능 요구사항

외부 API·로그인 없이 실행, TypeScript strict, lazy simulation, reduced motion, 키보드 조작, 입력 검증, IndexedDB 실패 처리. 브라우저 저장소의 origin별 격리와 JSON 백업 책임을 UI에 안내한다.

## 제약

PDF 참고 자료 미제공. 실제 3D, 외부 데이터 수집, AI, 출력 런타임 패키징은 후속. 배포 미허용. 사용자가 후속 지시로 GitHub push를 허용했으며 기능 브랜치를 사용한다.
